# kz-legal-corpus

Кодексы РК в Git: автоматическая выгрузка с adilet.zan.kz, отслеживание редакций.

## Что внутри

| Файл | Зачем |
|---|---|
| `seed/docids.txt` | Список документов. 23 действующих кодекса РК. Единственный файл, который вы редактируете. |
| `scripts/check_ids.py` | Проверяет, что все ID открываются, и печатает реальные названия. |
| `scripts/fetch.py` | Качает страницы, сравнивает хэш, сохраняет только изменившееся. |
| `scripts/normalize.py` | HTML → Markdown с шапкой (номер, название, дата редакции, хэш). |
| `.github/workflows/sync.yml` | Запуск по кнопке и по расписанию (понедельник, 02:00 UTC). |

## Первый запуск

1. Залейте файлы в репозиторий (Add file → Upload files), сохранив папки.
2. Actions → corpus-sync → Run workflow → поставьте галочку **Только проверить ID**.
3. Откройте лог шага «Проверка ID». Против каждого ID будет реальное название
   документа с сайта. Если что-то помечено БИТЫЙ — найдите документ на adilet
   и замените ID на хвост из адресной строки.
4. Запустите ещё раз без галочки. Появятся папки `raw/` и `corpus/`.

23 документа × 2 сек паузы ≈ полторы минуты на прогон.

## Дальше

* Каждый понедельник GitHub перепроверяет корпус сам.
* Изменение редакции видно как обычный git diff: `git log -p corpus/K2600000253.md`.
* Каждый прогон помечается тегом `corpus-ГГГГ.ММ.ДД` — это версия корпуса
  для ссылок в выводах системы.
* Для RAG индексируйте `corpus/`, не `raw/`.

## Ограничения

* Раздел `/rus/search/` закрыт в robots.txt — краулер туда не ходит,
  список ведётся вручную.
* Пауза 2 сек, один поток.
* СН РК и другие НТД сюда не добавляются: у них иной правовой режим.
* Для промышленного использования стоит запросить официальную выгрузку
  у РЦПИ / Минюста.
